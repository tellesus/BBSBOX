# Client identity signing core

Implementation reference for [M03](../../docs/development/modules/M03-identity-access.md) and the [public credential profile](../../crates/credentials/README.md). Product authority remains the canonical roadmap and user instructions.

This Rust library generates separate client-held person roots and device signing keys. A root issues a credential with a fresh random incarnation and explicit bounded purposes. A device activates only with the expected person's credential matching its own public key, then signs only delegated purposes. Consumers construct their domain-separated/resource-bound signed structure; receivers still verify resource authority and causal revocation.

Secret types have no Debug, Clone or plaintext serialization interface. Seeds and signing keys zeroize on drop through the maintained libraries. Public contact cards contain root public keys only. The node depends on the public verifier; this client key holder appears in node tests only.

M03 C adds protected recovery and account-link proofs below. M04 owns stream/counter integration; M13 owns MLS state. This cryptographic library has real tests; shipped native-client installation/update trust and phone tests remain separate gates. Run the root workspace checks from the repository root.

## Recovery profile 1

One shared `recovery::Engine` per client admits one expensive operation at a time on a blocking worker. The user-held kit is canonical CBOR `["bbsbox.recovery-kit/v1",1,1,salt_bstr16,nonce_bstr24,ciphertext_bstr]`. The first five fields encoded as an array are AEAD associated data. Protocol/profile 1 fix Argon2id v19 at 65,536 KiB/three passes/one lane/32-byte key and XChaCha20Poly1305 with a random 24-byte nonce. Each export uses fresh salt/nonce. Plaintext is the 32-byte person root seed followed by exactly the supplied private client state (maximum 8 MiB); the encrypted body adds the 16-byte authentication tag. The loader caps kit bytes at 8 MiB + 256, requires canonical flat structure (recursion limit four), validates profile/lengths before KDF work, and rejects wrong passphrase/tampering. Passphrases use the initial 15-character/1,024-byte policy, independent of node login passwords. Root seeds, plaintext, derived keys, passphrases and cipher keys zeroize through the owning types/features. [Argon2](https://docs.rs/argon2/0.6.0/argon2/) and [XChaCha20Poly1305](https://docs.rs/chacha20poly1305/0.11.0/chacha20poly1305/) supply the algorithms.

`import` returns `RestoredIdentity` with the same public person identity and supplied receive-side state. It exposes no old active signing device. `new_device` generates a new key, root-authorized credential and incarnation. `reexport` changes the kit passphrase without changing that person. Existing devices elsewhere require their normal revocation policy; changing a kit password does not revoke them. M13 must keep restored MLS state receive-only until a fresh owner-authorized join. Supplying this library an opaque state fixture does not establish that integration or recover unexported history.

## Destination-account proof

`RootKey`/`RestoredIdentity::prove_account_link` require the expected destination NodeId and local account ID and reject mismatched challenges before signing. `bbsbox.account-link/v1` uses canonical untagged COSE_Sign1/Ed25519 with the person digest as protected key ID and domain as external AAD. Payload is `[domain,1,node_digest_bstr32,local_account_bstr16,person_digest_bstr32,nonce_bstr32]`. Root possession is proved directly; scanning a public card or logging in alone cannot produce this proof. The native UI must obtain expected destination context through its authenticated local connection. Server linking and expiry are described in the [account reference](../../crates/identity/README.md).
