# Historical review of roadmap v1.0.0

Historical archive — not canon. Findings and check counts below apply to the reviewed revision, not automatically to later work. Current scope and validation come from the [roadmap](../development/README.md) and current user instructions.

# Senior development review and roadmap lock

Review date: 2026-10-25 · Tier 1 0.5.0 · Roadmap/contracts 1.0.0 · Authority U19 · [ADR-0001](../decisions/ADR-0001-roadmap-lock.md).

**Disposition: accepted for implementation after the corrections below.** This is a design and dependency review, not an implemented-system security audit or a claim that prototypes passed. All 32 modules remain Unstarted. The user authorized the defined proposal scopes and best-judgment selections; optional activation remains a SysOp choice, while D01–D07 remain deferred.

## Review method

Reviewed all 20 core and 12 expansion briefs against the master requirements, accepted P01–P24 register, T01–T14 decisions, five shared contracts and each module's completion evidence. Checked data ownership, prerequisites, delayed delivery, privacy boundaries, failure/recovery, acceptance coverage, integration responsibility and the size of the context needed for one module. Later user conclusions retain precedence over brainstorm suggestions. The lock does not add unbounded future features.

The selected stack is Rust/Axum/Tokio, SQLite WAL/rusqlite, static SvelteKit/TypeScript and signed CBOR/COSE events on Debian. MLS/OpenMLS and a separately signed Tauri client are selected for the private-client experiments. Their fitness is an explicit release gate. AGPL-3.0-or-later software and CC-BY-SA-4.0 project prose are adopted with their full texts and scope notice.

## Findings corrected before lock

| Finding | Correction and verification required during implementation |
| --- | --- |
| One chain per device could make a public event depend on hidden private/local predecessors. | C02 uses audience/resource-scoped device streams and writer incarnations. M04/M15 must prove a selective subscriber can progress without receiving unauthorized predecessors. |
| Convergence appeared to include arrival-dependent courier credit. | Replicated content/control converges for equal evidence/policy; local receipts and credits preserve actual intake history. M04/M16 verify these separately. |
| Separate game databases were outside a consistent core backup. | C01 adds coordinated checkpoints and a shared manifest; M11/M12 test worker failure, command draining, restore and reward replay. |
| Recovery language could imply no lost writes or duplicate physical effects after restoring an old snapshot. | Record the surviving recovery horizon, reconcile available evidence and start new signing incarnations. Uncertain coupon/reward records require local reconciliation; unrelated service continues. |
| Raw or invalid arrivals could reserve courier provenance. | C03 reserves first source only after bounded signature/signer/scope checks; rejection clears provisional association. M16 tests competing carriers, staged acceptance, duplicate direct mesh copies and crashes. |
| An origin-signed game export alone does not authorize its importer to claim the character. | C04 requires destination-bound owner proof and a fresh challenge, then configured game/GM acceptance. M18 tests stolen/replayed exports and destination mismatch. |
| Server-hosted crypto UI does not itself resist code substitution by that host. | C05 separates browser sessions from the independently trusted private client, scoped pairing tokens and pinned TLS. M00/M13 must demonstrate actual phone/desktop installation and update trust. |
| An encrypted fresh event needed a precise admission boundary for credit. | C05 specifies signed outer authority/routing fields and ciphertext hash. Host acceptance does not assert meaningful plaintext. M13 freezes proof bytes and M16 tests admission before awarding credit. |
| Suppression could be bypassed by ordinary sync/export or lose the reported revision. | M14/C05 preserve exact case targets, restrict normal read/search/export paths and permit case-scoped access for proven owner/moderator roles. M15/M16 own delayed case transport integration. |
| Withholding a suppressed post could also strand later events behind its chain gap. | C02 signs a detached-body commitment. Authorized same-scope consumers can verify continuity without receiving the suppressed body; proof-only intake earns no credit. Semantically dependent actions remain pending. |
| Provider completion depended on future consumers, creating implicit cycles. | M07/M09/M12 expose fixture-tested interfaces; M08/M10/M11/M16/M18 own real integrations. M13 owns encrypted friend audiences. Missing exchange, reward and recovery dependencies were added. |
| Foundation research could block all local work while phone encryption remained unresolved. | M01/M02 consume M00 G0-local evidence; M13 also requires its private-client/MLS evidence. The incomplete research remains visible and cannot pass G2. |
| A core pilot could be mistaken for completion of every approved expansion. | G4 covers the core pilot; G5 completes O01–O12. AC16 belongs to O11; achievements/progress completion of AC21 belongs to O12. AC23–AC34 cover each expansion. |
| Accepted alternatives and old proposal wording left unclear implementation boundaries. | Module defaults now select concrete kiosk, courier, reward, privacy, friendship, game and operational choices. Historical records remain historical; bounded defaults can evolve through the recorded change process. |

## Static verification and limits

Run `python tools/validate_roadmap.py` from the repository. It validates all 32 module IDs, topological order, prerequisite agreement across briefs/index/graph, referenced decisions/contracts, all R/P/AC coverage owners, D/N presence, review/ledger entries, baseline versions, local document links and license texts. Each reading packet includes START_HERE, one brief and its listed contracts; the limit is 2,500 words before small targeted decision-row lookups.

The final check passed on 2026-10-25: 32 modules, 28 requirements, 24 accepted proposal records, 34 acceptance criteria, 14 technical decisions, five contracts, all 733 local Markdown links and both license texts. All module packets remain below 2,500 words. `git diff --check` also passed. Static consistency does not prove protocol convergence, encryption behavior, offline phone installation, hardware support, capacity, backup recovery or game correctness. Those remain the named module/gate fixtures above. No application implementation or device test was performed for this lock.
