# ADR-0002 — explicit wire algorithms and event boundaries

2026-10-31 · Accepted implementation rationale · Reference only. Current authority is [C02](../development/contracts/C02-identity-events.md), [M03](../development/modules/M03-identity-access.md), [M04](../development/modules/M04-signed-events.md) and user instructions.

The first reusable credential/link profile used COSE's polymorphic EdDSA identifier (-8) while enforcing Ed25519 keys. [RFC 9864](https://www.rfc-editor.org/rfc/rfc9864.html) deprecates that label and defines the explicit Ed25519 identifier (-19). New device credentials and account-link proofs therefore use profile v2 with algorithm -19 and versioned domains/payload version 2. Existing v1 records retain their exact bytes/IDs and verify under their original fixed Ed25519 interpretation. New issuance refuses v1; algorithm relabeling/downgrade fails canonical reconstruction. Accepted old link receipts remain retryable from their stored signed bytes. Person/device/node/forum/courier IDs and public QR cards remain unchanged because the key curve/ID derivation did not change. Recovery kit v1 also remains unchanged.

The initial event wire format v1 starts with -19. Its metadata commits all routing, identity, resource/audience/distribution, incarnation, chain, dependencies, claimed time and detached-body hash/length. Typed dependency namespaces prevent equal event/credential/blob digests from being conflated. Stream IDs also bind actor role/subject; scope changes cannot share a predecessor chain. Body and envelope limits precede parsing/signing; exact independent vectors include unsigned/signed 64-bit boundaries.

Signature verification, actual body verification, kind/actor/purpose gates, required-extension validation, causal/resource authorization and reducer integration remain distinct steps. Optional annotations never create authority. Unknown required semantics stay unsupported; no content/credit acceptance follows from merely storing a commitment. M04 B/C supply actual durable staging, forks and convergence, while M13 owns encrypted admission and private-client integration. The codec's pure production dependency graph enables key holders and receivers to share bytes without giving the node client-held roots.

This refines implementation within approved T04/T05/T08 scopes. It creates no new product feature or shipped device/support claim. The independent M00 v0 experiment retains its historical lockfile/profile as reference evidence.
