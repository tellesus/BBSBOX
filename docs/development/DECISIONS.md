## Implementation evidence — 2026-10-30

T01–T05 have an initial Windows-only M00 experiment: Axum 0.8.9, rusqlite 0.41.1, coset 0.4.2, ed25519-dalek 2.2.0 and the locked SvelteKit/TypeScript build. Rust/API/store tests and actual HTTPS browser journeys pass. The node fixture signs this disposable public test stream; it does not establish personal identity. Rust 1.99.1 and Node 24.22.1 are the tested build toolchains. Lockfiles record transitive versions.

This is partial evidence for the selected architecture, not a gate pass or support matrix. T06 now has eight passing local OpenMLS fixtures covering disconnected work, removal, retention, forks and protected state recovery. T07 trusted private-client distribution and milestone phone enrollment remain unverified. T08 production recovery is not established by a process restart. Dependency license metadata is recorded with the experiment; local source/license release packaging remains M12 work. WORK_LEDGER owns the actual execution record.

## Local MLS findings — 2026-10-30

OpenMLS 0.9.2 with RustCrypto/basic-credential/traits 0.6.0 passes eight three-client fixtures. Raw membership permits non-owner commits and incompatible branches; C05 therefore requires separately authenticated owner approval before merge. Retention of 32 past epochs admits delayed work after 32 updates, not indefinitely. Old backup restoration loses later replay knowledge; the tested recovery guard remains receive-only until new owner-authorized membership state. A new group commit alone cannot establish that an old restored sender state is fresh. These are inputs to M13, not a shipped encrypted-forum claim.

Phone tests are deliberately scheduled at G1 public alpha/G2 private-client release. Local native/CI work continues while those checks remain pending. The [experiment record](../../spikes/m00/mls/README.md) describes exact fixtures and remaining authority/client integration.

## Reference sources for the selected technologies

- [Axum](https://docs.rs/axum/latest/axum/) describes the HTTP framework and Tokio integration.
- [SvelteKit static adapter](https://svelte.dev/docs/kit/adapter-static) supports a locally served static build; our authenticated app routing still needs its prototype.
- [SQLite WAL](https://www.sqlite.org/wal.html), [backup API](https://www.sqlite.org/backup.html), and [rusqlite](https://docs.rs/rusqlite/latest/rusqlite/) inform concurrency and snapshot design. WAL has one writer and requires local shared-memory access; it is not a network database replication mechanism.
- [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html) and [RFC 9052](https://www.rfc-editor.org/rfc/rfc9052.html) define CBOR/COSE; our application profile and vectors still need specification.
- [RFC 9420](https://www.rfc-editor.org/rfc/rfc9420.html) and [OpenMLS](https://book.openmls.tech/) establish the MLS candidate. OpenMLS lists mobile/WASM targets as built but not tested on upstream CI; library availability is not proof of our supported-device behavior.
- [Browser secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts) and [Tauri distribution](https://v2.tauri.app/distribute/) inform client feasibility. Neither guarantees frictionless offline installation on every phone.

References were inspected on 2026-10-25. Dependency pins are produced when implementation starts; hardware compatibility remains empirical.
